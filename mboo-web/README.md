# Mboo Web

**Mboo Code 的 Next.js Web 工作台。**

前端通过同源 Route Handler（Next.js 的服务端接口代理）访问 Spring Boot 后端，浏览器不会直接跨域请求后端。工作台负责展示会话过程、工具调用、授权状态、模型能力和上下文资源，并保持实时事件与历史回放一致。

## 1. 项目定位：让 Agent 的执行过程可见、可控

- **同源后端代理**：浏览器只访问 `/api`，由 Next.js 服务端转发到后端，避免跨域配置和后端地址暴露到浏览器运行环境。
- **实时与历史一致**：聊天和上下文压缩通过 Server-Sent Events（SSE，服务端持续推送事件）实时更新；重新打开会话时通过历史事件还原相同过程。
- **任务资源可观察**：输入区显示当前模型、思考深度、工作区、上下文用量和压缩状态，避免长会话在资源耗尽后才发现问题。
- **权限由用户确认**：工具需要授权时，页面提供本次允许、会话内允许和拒绝三种明确操作。

## 2. 核心能力

### 2.1 会话与工作区

- **会话全生命周期管理**：支持新建、打开、重命名、归档、恢复和删除会话。
- **工作区分组**：支持选择本机目录、保存工作区、按工作区查看会话和删除工作区记录。
- **安全删除语义**：删除工作区会删除应用内工作区记录及其下属会话，不会删除用户选择的真实项目目录。
- **历史过程回放**：重新打开会话时恢复用户消息、助手消息、工具调用、授权、错误、取消及上下文压缩事件。

### 2.2 模型与上下文

- **模型候选动态加载**：模型列表由后端在启动时从供应商模型列表读取并缓存；候选加载失败时仍可手动输入模型 ID。
- **模型能力动态匹配**：前端按后端返回的模型元数据展示工具调用、附件、上下文窗口和思考深度能力，不使用固定模型能力表。
- **思考深度按模型显示**：仅展示当前模型 `reasoning_options` 中 `effort` 类型的档位。已知档位会显示为“无、极低、低、中、高、极高、最高”，实际可选项由模型决定。
- **上下文窗口可配置**：支持读取、保存和恢复单模型的上下文窗口上限；前端用生效上限计算用量占比。
- **上下文压缩可追踪**：支持手动压缩；压缩的开始、完成、跳过、失败和取消状态都会在页面中展示并写入会话历史。

### 2.3 工具执行与授权

- **工具轨迹可视化**：展示工具开始、等待授权、结束和失败状态，并可查看结果详情及原始内容。
- **授权卡片可操作**：对 `TOOL_APPROVAL_REQUIRED` 事件提供 `ALLOW_ONCE`（允许本次）、`ALLOW_SESSION`（本会话允许）和 `DENY`（拒绝）操作。
- **输出详情按需读取**：工具结果预览随会话事件展示，原始内容通过独立接口加载，避免大型命令输出影响主页面性能。

## 3. 启动

### 3.1 启动后端

先在项目根目录启动后端：

```powershell
.\gradlew.bat bootRun
```

macOS / Linux：

```bash
./gradlew bootRun
```

### 3.2 启动前端

```bash
cd mboo-web
npm install
npm run dev
```

打开 [http://localhost:3000](http://localhost:3000) 使用工作台。

默认后端地址为 `http://localhost:8080`。后端不在默认地址时，在启动前端前设置服务端环境变量：

Windows PowerShell：

```powershell
$env:MBOO_API_BASE_URL="http://localhost:8080"
npm run dev
```

macOS / Linux：

```bash
MBOO_API_BASE_URL="http://localhost:8080" npm run dev
```

当前版本仅支持 OpenAI Responses API 接口，不支持 Chat Completions API，也不支持通过 `provider` 切换其他模型供应商。后端 `.mboo/setting.json` 使用 `api_key` 和 `base_url` 配置模型服务。

## 4. 目录结构

```text
mboo-web/
├── public/                    # 静态图片和界面资源
├── src/
│   ├── app/                   # Next.js 页面、全局样式和同源 API 代理
│   │   ├── api/               # 会话、模型和工作区的 Route Handler
│   │   ├── preview/           # 独立预览页面
│   │   └── page.tsx           # 工作台页面与会话状态编排
│   ├── components/            # 跨功能区复用组件
│   ├── features/              # 按业务界面划分的功能组件
│   │   ├── composer/          # 输入区、模型、推理和工作区设置
│   │   ├── context-rail/      # 上下文状态面板
│   │   ├── conversation/      # 消息列表和会话状态
│   │   ├── sessions/          # 会话列表与工作区导航
│   │   ├── tools/             # 工具轨迹、结果和授权卡片
│   │   └── workbench/         # 工作台布局和顶部栏
│   ├── lib/                   # 后端代理、SSE 解析、类型和运行时状态
│   └── styles/                # 全局主题定义
├── package.json               # 前端脚本和依赖
└── README.md                  # 前端工作台说明
```

- `app/page.tsx` 负责组合工作台区域和协调会话状态，不承载可复用的独立界面实现。
- `features` 按用户可见的业务区域拆分，组件样式与组件文件同目录维护。
- `app/api` 仅负责同源代理和传递后端响应，不在前端重复实现后端业务规则。
- `lib` 维护与界面无关的请求、事件流和状态工具，避免与具体组件相互耦合。

## 5. 使用工作台

### 5.1 开始一个任务

1. 在输入区的“模型”中选择候选模型；候选加载失败时可以切换到“手动输入”。
2. 需要时选择思考深度。下拉框只显示当前模型实际支持的档位，默认值交由模型服务决定。
3. 选择一个已有工作区，或通过“选择目录”指定当前任务的代码仓库；未选择目录时，后端会为新会话创建独立默认工作区。
4. 输入任务并发送。生成过程中可停止当前生成；消息、工具调用和授权请求会在会话区持续更新。

### 5.2 管理会话与工作区

- 在左侧会话列表中创建、打开、重命名、归档、恢复或删除任务。
- 工作区用于把任务按项目目录聚合。删除工作区只清除 Mboo Code 内的记录和关联会话，不会删除原项目文件。
- 打开历史会话时，工作台会恢复历史消息、工具过程、压缩记录和授权结果，便于接续任务或排查执行过程。

### 5.3 管理上下文

- 输入区的上下文状态显示当前会话的 token（模型处理文本的计量单位）用量、模型上限和压缩状态。
- 模型设置支持调整上下文窗口上限；该上限用于计算使用率和决定何时压缩历史内容。
- 上下文接近上限时可以手动压缩。压缩会保留任务摘要和近期对话，减少历史内容占用；压缩失败或被跳过时不会清空已有上下文用量。

### 5.4 处理授权与工具结果

- 工具需要确认时，选择“允许本次”只授权当前调用；选择“本会话允许”在该会话内复用授权；选择“拒绝”会阻止该调用。
- 工具结果卡片展示执行状态与摘要。对于命令输出等大内容，可展开查看详情或原始输出。

## 6. 前端运行行为

- 前端通过同源 `/api` 路由代理后端请求，默认代理目标为 `http://localhost:8080`。
- 聊天与上下文压缩使用 SSE 实时更新；页面刷新或重新打开会话时，从后端历史事件恢复界面状态。
- 模型候选和能力在后端启动时加载。更新供应商模型配置后，需要重启后端才能刷新候选与能力信息。
- 接口字段与事件载荷说明见根目录 [README](../README.md) 和 [Session Event Payload 字段说明](../docs/会话事件Payload字段说明.md)。
