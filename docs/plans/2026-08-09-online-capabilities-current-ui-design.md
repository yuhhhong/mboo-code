# 线上能力接入当前前端设计

> 设计状态：已确认，后端同步线上最新版本后冻结，功能开发仅修改前端，暂不进入代码开发
> 日期：2026-08-09
> 适用分支：当前 `main` 工作区及后续集成分支

## 1. 目标

以后端 `origin/main` 最新完整版本为不可变基线，在不对后端做二次修改的前提下，保留当前前端视觉、组件边界和交互密度，接入线上后端已经具备、但当前前端尚未完整对接的四类能力：

1. 工作区持久化管理；
2. 会话级完全访问模式；
3. 模型上下文上限配置；
4. 上下文用量和上下文压缩。

本次不重做当前已经具备的会话管理、模型选择、目录选择、流式消息、工具结果、工具授权和主题样式。

## 2. 设计基线

### 2.1 后端同步与契约基线

后端行为、接口契约和 SSE 事件以远程 `origin/main` 最新完整版本为准。集成分支直接从最新 `origin/main` 建立，完整保留其中的 Java、数据库、Gradle、Prompt 和相关配置，不只挑选近期功能提交。基线建立后，功能开发不再修改后端文件。

近期直接涉及目标能力的远程提交包括：

- `e916434`：工作区持久化管理及前端工作区接口；
- `9707f48`：工作区路径服务调整；
- `c2a2c63`：会话未开始时支持完全访问；
- `dd51a89`：模型上下文上限自定义；
- 更早的上下文用量和上下文压缩完整依赖链。

### 2.2 前端基线

当前前端 UI 规范和实现作为视觉基线：

- `/preview` 的 `1440 × 900` 画板；
- `280px / minmax(0, 1fr) / 250px` 三栏布局；
- 白色工作区、中性灰结构、紫色动作点缀；
- 消息区唯一主滚动槽；
- composer 固定在主区底部；
- 授权详情和长结果在局部容器内滚动；
- 展示组件使用 feature 组件和 CSS Module；
- SSE、会话 CRUD、模型状态和授权回调仍由页面层统一编排。

当前工作区存在未提交的前端重构和未跟踪设计资产，实施前必须建立可恢复快照，不允许覆盖或回退这些内容。为避免直接 `pull` 产生前端冲突，使用基于 `origin/main` 的独立集成分支承载最新后端，再迁入当前本地前端。

## 3. 功能范围

### 3.1 工作区管理

当前已有目录选择和会话工作区路径展示，本次只增加持久化工作区实体能力：

- 获取工作区列表；
- 将目录保存为工作区；
- 新建会话时选择工作区；
- 历史会话展示关联工作区；
- 删除工作区及应用内关联关系；
- 删除前提示关联会话数量；
- 明确说明不会删除磁盘目录。

工作区路径选择仍复用当前 `TaskComposer` 的目录选择流程，不新增第二套路径选择器。

对应接口：

- `GET /workspace/list`；
- `POST /workspace`；
- `DELETE /workspace/{workspaceId}`。

### 3.2 会话级完全访问

在当前任务设置区域增加权限模式选择：

- `DEFAULT`：按现有工具权限规则逐项审批；
- `FULL_ACCESS`：会话级工具调用自动通过。

规则：

- 新会话在 `ChatReq` 中提交 `permissionMode`；
- 已有会话通过 `PUT /session/{sessionId}/permission-mode` 更新；
- 会话切换时从会话元数据恢复模式；
- 前端不缓存或推断工具目录权限；
- 后端实际发送的授权事件仍然优先展示，前端不提前假设成功。

### 3.3 模型上下文上限

当前模型选择和手动输入能力继续保留，在模型信息区域增加上下文配置：

- 展示当前模型的有效上下文上限；
- 展示模型允许的最小值和最大值；
- 对支持调整的模型展示滑块或等价控件；
- 支持保存自定义上限；
- 支持恢复默认上限；
- 模型切换时清理旧模型的配置和加载状态。

对应接口：

- `GET /config/modelContextLimit?modelId={modelId}`；
- `PUT /config/modelContextLimit?modelId={modelId}`；
- `DELETE /config/modelContextLimit?modelId={modelId}`。

前端通过 Next.js API 代理转发，不在组件内拼接后端地址。

### 3.4 上下文用量和压缩

上下文状态属于当前会话状态，优先展示在 `ContextRail`，不放入消息正文布局。

用量展示至少包括：

- 已用 token；
- 当前有效上限；
- 使用比例；
- 无数据时的明确占位状态。

压缩交互：

- 提供手动压缩入口；
- 压缩期间禁用重复触发和新任务发送；
- 运行状态栏显示“正在压缩上下文”；
- 使用现有停止机制处理可取消的压缩请求；
- 完成、失败、跳过通过系统信息提示展示；
- 不把压缩过程伪装成普通助手消息；
- 压缩完成后重新获取或清理当前用量。

需要接入的事件类型：

- `CONTEXT_USAGE_UPDATED`；
- `CONTEXT_COMPRESSION`。

对应接口：

- `POST /session/{sessionId}/context/compress`。

实时 SSE 和历史 JSONL 必须共用同一套事件归并逻辑。历史回放中，已完成压缩事件用于恢复上下文状态边界；未完成压缩不能被渲染成正在运行的假状态。

## 4. 前端组件归属

| 组件 | 负责内容 | 不负责内容 |
|---|---|---|
| `SessionListPanel` | 工作区列表入口、工作区关联会话、删除确认 | 直接调用后端接口 |
| `TaskComposer` | 权限模式、模型配置、上下文压缩入口 | 解析 SSE 或修改会话元数据 |
| `ContextRail` | 当前模型、工作区、上下文用量、压缩状态、通知 | 发起工具授权决策 |
| `ToolApprovalCard` | 工具授权展示和三种决策按钮 | 缓存会话权限 |
| `ToolTrace` | 工具状态、结果引用和结果加载状态 | 维护另一套事件归并逻辑 |
| `MessageList` | 助手消息、系统信息和压缩结果提示 | 直接访问后端 |
| 页面层 `page.tsx` | API 调用、SSE、会话 CRUD、领域状态和回调 | 承载大量局部 CSS |

## 5. 统一数据流

```text
后端 API / SSE / JSONL
        ↓
统一 TypeScript 类型和事件解析
        ↓
页面层领域状态
        ↓
feature 组件 props
        ↓
当前主题下的展示与交互
```

禁止以下做法：

- 组件内部直接复制 SSE 监听；
- 实时事件和历史事件使用两套解析方法；
- 前端根据按钮点击提前伪造后端成功状态；
- 通过新增全局颜色或改变父级尺寸解决功能展示问题；
- 用线上单体 `page.tsx` 覆盖当前组件化前端。

## 6. 后端同步与冻结边界

以下内容必须完整采用 `origin/main` 最新版本：

1. `src/main/java/**`；
2. `src/main/resources/db/**`；
3. `src/main/resources/prompt/**`；
4. `build.gradle`、`settings.gradle` 和 Gradle Wrapper；
5. 后端 DTO、Controller、Service、Mapper、数据库迁移、权限链和上下文服务。

集成分支建立后，上述范围相对 `origin/main` 必须保持零差异。前端通过 Next.js API Route 代理调用线上已有接口，并按照线上事件 Payload 做类型适配。如果真实后端接口缺失或与远程契约不一致，停止前端任务并报告，不通过修改后端兜底。

- 工作区可保存、切换和删除，删除不影响磁盘目录；
