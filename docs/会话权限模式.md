# ADR-0001：会话权限模式（默认权限 / 完全访问）

- 状态：已接受
- 日期：2026-08-06
- 相关文档：`docs/工具与工作区权限方案.md`

## 背景

现有权限内核按会话评估工具调用，单次评估产出 `ALLOWED` / `NEED_ASK` / `ERROR` 三态（见权限方案第 3 节）。`NEED_ASK` 会推送 `TOOL_APPROVAL_REQUIRED` 授权卡片并阻塞等待用户决策。实际使用中，高频的写入、命令授权打断节奏，用户希望提供"完全访问"模式：开启后工具调用的授权自动通过，不再询问。

## 决策

1. **新增会话级权限模式** `permissionMode`，取值 `DEFAULT`（默认权限）/ `FULL_ACCESS`（完全访问），存储在 `Sessions.metadataJson` 顶层节点（与 `permissions` 平级），不放进 `permissions` 节点内部——它是行为开关，不是授权数据。字段缺失时按 `DEFAULT` 处理，兼容历史会话。
2. **完全访问只压 `NEED_ASK`**：评估结果为 `NEED_ASK` 的权限要求自动视为 `ALLOWED`；`ERROR`（路径缺失/无法解析等硬错误）和内置命令黑名单（`COMMAND_PERMISSION_DENIED`）照常拒绝，安全硬边界不因模式改变。
3. **每次评估实时读取模式**：初评（`requestIfNeeded`）与执行前复核（`verifyFinalPlan`）使用同一转换逻辑，保证两处判定一致。会话中途切换模式只影响下一次调用的评估；已挂起等待的授权卡片保持原状，不自动放行也不取消。
4. **不留审计痕迹**：完全访问下自动通过不产生 `TOOL_APPROVAL_REQUIRED` 事件，也不写入 `ALLOW_SESSION` 会话授权数据（没有卡片就没有会话授权动作）。已持久化的历史会话授权继续保留并生效。
5. **创建时初始化，创建后走专用修改接口**：`POST /session/chat` 增加可选 `permissionMode`，仅在 `sessionId` 为空并创建新会话时写入初始模式；已有会话忽略该字段，继续使用 `PUT /session/{id}/permission-mode` 修改，底层复用 `updateMetadataJson` 的分段锁 + CAS 读改写机制，避免与 `permissions` 节点更新互相覆盖。
6. **前端交互**：在发送按钮同行靠左位置放置模式下拉框（默认权限 / 完全访问），切换不弹二次确认；会话未创建时允许切换，本地保存选择并在首条 `/chat` 请求中携带；新建任务默认"默认权限"；归档会话中下拉框禁用（只读展示当前模式）；不考虑多标签页实时同步，刷新或重进会话后一致。

## 备选方案

| 备选 | 结论 | 原因 |
| --- | --- | --- |
| 完全访问连内置命令黑名单也放行 | 否决 | 黑名单是防危险命令的最后硬边界，模式开关不应覆盖 |
| 模式存入 `permissions` 节点 | 否决 | 模式是开关而非授权数据，平级存放语义更清晰 |
| 全局权限模式（影响所有会话） | 否决 | 权限内核边界为"只实现会话内权限管理"，不做全局 |
| 切换模式时自动放行已挂起的授权卡片 | 否决 | 实现复杂且语义混乱，切换仅影响下一次评估足够直观 |
| 自动通过时落审计事件 | 否决 | 用户明确不需要，保持事件流干净 |

## 影响

- `SessionPermissions` 不变；`metadataJson` 增加顶层 `permissionMode` 字段。
- `ToolApprovalService` / 评估链路增加"模式转换"步骤：`FULL_ACCESS` 下 `NEED_ASK → ALLOWED`，初评与复核共用。
- `SessionService` 增加模式读写方法，走现有 `updateMetadataJson` 并发保护。
- 前端会话输入区增加模式下拉框，从会话详情（`Sessions.metadataJson`）读取当前值。
- 实施完成后需同步更新 `docs/工具与工作区权限方案.md`。
