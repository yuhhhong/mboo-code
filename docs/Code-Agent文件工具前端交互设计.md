# Code Agent 文件工具前端交互设计

## 1. 文档状态

- 状态：已实施。
- 更新时间：2026-07-27。
- 适用范围：当前 `mboo-web` 前端。
- 后端接口基线：`docs/Code-Agent文件工具后端接入设计.md`。
- 会话事件基线：`docs/会话事件Payload字段说明.md`、`docs/会话JSONL事件日志设计.md`。
- 本文只描述五个文件工具的前端交互与展示，不修改后端工具、权限和事件设计。

## 2. 目标

在保留当前 QQ 主题、助手消息结构和工具轨迹交互的基础上，为以下五个文件工具补充清晰、一致的前端展示：

1. `glob_files`：查找文件。
2. `search_text`：搜索文本。
3. `read_file`：读取文件。
4. `edit_file`：编辑文件。
5. `write_file`：写入文件。

前端需要做到：

- 工具调用继续归属到对应助手消息，不脱离会话上下文。
- 用户能快速识别工具、目标路径、当前状态和执行耗时。
- 授权卡片明确展示授权目录和授权有效范围，但不展示修改前 diff。
- 文件读取、搜索和修改结果在当前工具卡片中可读、可滚动、可复制。
- `edit_file`、`write_file` 执行成功后能够展示修改摘要和 unified diff。
- JSONL 历史回放与 SSE 实时事件使用同一套归并和展示逻辑。
- 新事件中的结果引用缺失或结果文件损坏时只影响当前工具项，不导致页面异常；旧结果事件不提供兼容读取。

## 3. 非目标

本阶段不处理：

- 新增或修改后端事件类型、授权接口和会话接口。
- 修改后端权限模型、授权范围或授权持久化逻辑。
- 修改前 diff 预览和逐次修改确认。
- 独立权限管理、授权列表、权限撤销和权限编辑页面。
- `run_command`、`apply_patch`、删除、移动和后台命令的前端交互。
- 图片、PDF、Notebook 等非文本文件预览。
- 独立文件浏览器、代码编辑器、diff 弹窗或全屏 diff 页面。
- 对现有页面布局和 QQ 主题进行无关重构。

## 4. 当前前端基线

当前代码已经具备完整的通用工具轨迹能力：

- `mboo-web/src/lib/session-types.ts` 定义工具开始、授权和结束事件。
- `mboo-web/src/app/page.tsx` 中的 `ToolTrace` 和 `ToolTraceItem` 负责工具展示。
- 工具调用通过 `messageId` 和 `toolCallId` 归并到对应助手消息。
- 工具轨迹采用两级折叠：助手消息中默认只显示工具汇总，展开后显示工具调用记录，每条记录再次展开后才显示参数和结果。
- 授权卡片支持 `ALLOW_ONCE`、`ALLOW_SESSION` 和 `DENY`。
- 提交授权时进入 `submitting`，请求失败后恢复 `waiting_approval`。
- 实时 SSE 和历史 JSONL 均通过 `toToolCallView` 与 `upsertToolCallSnapshot` 生成相同视图。
- 历史回放中未完成的授权请求会标记为失败，并显示“授权请求已失效”。
- 右侧通知区已经统计 `waiting_approval` 和 `submitting` 状态数量。

本阶段在该能力上增量实现，不建立另一套文件工具卡片体系。

## 5. 核心设计结论

### 5.1 复用现有工具轨迹

- 五个文件工具继续使用 `ToolTrace/ToolTraceItem`。
- 工具轨迹仍显示在对应助手消息正文之后。
- 工具汇总和单条工具记录均默认折叠，避免连续工具调用刷屏。
- 保持当前统一的“🔧”标识，不为每个文件工具引入独立图标。
- 保持折叠标题、状态、耗时、参数、结果、错误和授权区域的现有层级。

### 5.2 不新增事件和接口

继续使用：

- `TOOL_CALL_STARTED`
- `TOOL_APPROVAL_REQUIRED`
- `TOOL_CALL_ENDED`
- `POST /api/session/{sessionId}/approvals/{approvalId}`

前端不要求后端新增“授权已处理”“diff 已生成”或“文件修改完成”等事件。

### 5.3 JSONL 与 SSE 同构展示

- 后端写入 JSONL 的事件与通过 SSE 发送的事件内容一致。
- 前端不得针对实时事件和历史事件维护两套文件工具解析逻辑。
- 实时状态和历史状态均由同一 `toToolCallView` 转换。
- `TOOL_CALL_ENDED` 只携带 `resultId` 和结果元数据，前端展开工具项时懒加载最多 4,000 字符的展示摘要。
- 后端结果制品中的截断占位符必须原样显示，不能由前端隐藏或替换。

### 5.4 授权阶段不展示 diff

- `edit_file`、`write_file` 的授权请求只展示工具、目标路径、授权说明和授权目录。
- 不展示 `oldText`、`newText`、`content` 或修改前 diff。
- 修改摘要和 diff 只在 `TOOL_CALL_ENDED` 后展示。
- 即使最终结果为 `NO_CHANGES`，此前已经产生的授权请求仍按普通授权流程展示。

## 7. 前端视图模型

### 7.1 `ToolCallView` 调整

在现有字段基础上增加解析后的展示信息：

```ts
type ToolCallView = {
  id: string;
  turnId?: string | null;
  toolName: string;
  status: ToolCallStatus;
  argumentsText: string;
  parsedArguments?: Record<string, unknown>;
  pathText?: string;
  resultId?: string;
  resultSizeBytes?: number;
  rawOutputAvailable?: boolean;
  errorCode?: string;
  errorMessage: string;
  durationMs?: number;
  createdAt?: string;
  approvalId?: string;
  approvalTitle?: string;
  approvalDescription?: string;
  permissionType?: ToolPermissionType;
  grantPath?: string;
};
```

说明：

- `argumentsText` 保存格式化后的安全参数文本。
- `parsedArguments` 仅在 `arguments` 能解析为 JSON 对象时存在。
- `pathText` 从五个文件工具的 `path` 参数中提取，用于折叠标题。
- `errorCode` 来自 `TOOL_CALL_ENDED`，与中文错误信息同时展示。
- 不在视图模型中保存 `oldText`、`newText` 或 `content`。

### 7.2 参数解析

新增独立的参数解析函数：

1. `arguments` 为空时返回空文本。
2. `arguments` 为 JSON 字符串且根节点为对象时：
   - 保存为 `parsedArguments`。
   - 使用两空格缩进生成 `argumentsText`。
3. JSON 解析失败时保留原始字符串，兼容旧事件和非 JSON 工具。
4. 不对字符串内容执行 HTML 渲染，统一按纯文本展示。

### 7.3 路径摘要

五个文件工具从 `parsedArguments.path` 提取路径：

- 折叠标题显示“工具名称 · 路径”。
- 使用单行截断，避免长绝对路径挤压状态和耗时。
- DOM `title` 保留完整路径，鼠标悬停可查看。
- Windows 路径保持后端原始形式，不在前端重新规范化。
- 参数无法解析或没有 `path` 时只显示工具名称。

示例：

```text
读取文件 · src/main/java/com/yu/App.java
搜索文本 · F:\code\project
```

## 8. 工具轨迹布局

### 8.1 工具汇总标题

助手消息中的工具轨迹默认只显示一行汇总：

- 对应助手消息仍处于流式执行状态时持续显示“调用工具中”，不能在连续工具调用的间隙提前切换为完成文案。
- 存在待授权工具时额外显示“等待授权”状态提示。
- 收到助手终态消息、确认本轮工具链结束后，一个工具显示“调用了一个工具”，多个工具显示“调用了多个工具”。
- 右侧显示工具调用数量。
- 点击汇总标题后展开或折叠内部工具调用记录。

### 8.2 单条工具标题

标题从左到右展示：

1. “🔧”和中文工具名称。
2. 可用时展示目标路径摘要。
3. 状态标签。
4. 执行结束后展示耗时。

路径使用弱化等宽字体，状态和耗时不能被长路径挤出可视区域。

### 8.3 默认展开规则

- 工具汇总默认折叠，运行状态变化时不自动展开。
- 用户展开工具汇总后，只显示工具调用记录列表。
- 每条工具调用记录默认折叠，用户再次点击后才显示参数、结果、错误或授权卡片。
- 用户手动控制的展开状态不因工具状态变化或父组件渲染而被重置。

### 8.4 单条工具展开区域

按以下顺序展示：

1. 原始工具名，仅在中文名称与工具名不同时显示。
2. 格式化后的安全参数。
3. 执行结果或修改摘要。
4. 错误信息和错误码。
5. 待授权卡片。

参数区和结果区继续使用等宽字体、保留换行并允许滚动。

### 8.5 复制能力

参数区和结果区各提供一个轻量复制按钮：

- 参数复制 `argumentsText`。
- 结果复制按 `resultId` 懒加载得到的 `resultPreview`，包括后端截断占位符。
- 复制成功只提供短暂的本地状态提示，不写入会话事件。
- 浏览器拒绝剪贴板权限时显示非阻塞错误提示。

## 9. 授权交互

### 9.1 授权卡片内容

授权卡片继续显示：

- `approvalTitle`
- `approvalDescription`
- 当前工具的目标路径，可从折叠标题或参数区查看
- `grantPath`
- “包含其子目录”说明
- 单次允许、会话允许和拒绝按钮

`READ/WRITE` 权限必须展示真实授权目录。`TOOL` 权限保持现有工具级文案。

### 9.2 按钮文案

保持现有文案：

| 权限类型 | 会话允许按钮 |
| --- | --- |
| `READ` | 本会话允许读取此目录 |
| `WRITE` | 本会话允许读写此目录 |
| `TOOL` 或历史缺失值 | 本会话始终允许此工具 |

其他按钮：

- `ALLOW_ONCE`：仅允许本次
- `DENY`：拒绝

### 9.3 提交状态

- 用户点击任一决策后立即进入 `submitting`。
- `submitting` 时禁用全部决策按钮，避免重复提交。
- 授权接口成功后不在前端猜测下一状态，等待后端 SSE 的开始或结束事件。
- 请求失败时恢复 `waiting_approval`，保留卡片并显示请求错误。
- 用户允许后通常收到 `TOOL_CALL_STARTED`，随后收到 `TOOL_CALL_ENDED`。
- 用户拒绝、超时或权限校验失败时可能直接收到失败的 `TOOL_CALL_ENDED`，不能依赖一定存在开始事件。

### 9.4 会话级授权

用户选择 `ALLOW_SESSION` 后，后续同目录调用可能不再产生授权卡片。前端只根据实际事件展示，不自行缓存或推断目录权限。

### 9.5 历史失效授权

历史回放中只有 `TOOL_APPROVAL_REQUIRED`、没有结束状态的调用：

- 状态转为 `failed`。
- 清除 `approvalId`。
- 显示“授权请求已失效”。
- 不展示可点击授权按钮。
- 不重新调用授权接口。

## 10. 结果展示

### 10.1 通用规则

- `resultId` 为空时不请求结果；加载后的 `resultPreview` 为空时不渲染结果区。
- 结果统一按纯文本处理，不使用 `dangerouslySetInnerHTML`。
- 前端不再次裁剪后端已经限制到 4,000 字符的结果摘要。
- 结果容器设置最大高度并允许滚动，不能撑开整个消息列表。
- 后端中间截断占位符原样显示：

```text
...（已截断，省略 xxx 个字符）...
```

### 10.2 `glob_files`

- 使用等宽文本展示文件列表和统计信息。
- 保留绝对路径或工作区相对路径的后端输出形式。
- 长路径允许横向或自动换行，但不能溢出工具卡片。
- 后端返回 `truncated=true` 时直接显示结果中的截断信息，不新增前端推断。

### 10.3 `search_text`

- 使用等宽文本展示路径、行号、匹配片段和统计信息。
- 保留行号和代码换行。
- 不在前端重新执行关键词高亮，避免正则、转义和截断结果产生不一致。
- 搜索结果过长时依赖后端事件截断占位符。

### 10.4 `read_file`

- 使用等宽文本保留后端带行号内容。
- 使用 `white-space: pre` 或等价行为，避免代码缩进被压缩。
- 长行在结果容器内滚动，不修改后端行号和省略占位符。
- 前端不自动发起下一页读取；分页由 Agent 继续调用 `read_file`。

### 10.5 `edit_file` 与 `write_file`

成功后展示：

- 操作类型：`CREATE`、`EDIT`、`OVERWRITE` 或 `NO_CHANGES`。
- 目标路径。
- 新增、删除行数。
- 修改前后字节数。
- `edit_file` 的替换次数。
- 执行后的 unified diff。

授权阶段不展示上述 diff。

### 10.6 Diff 展示

新增本地 `DiffPreview` 展示组件或等价局部渲染逻辑，按行处理纯文本：

| 行类型 | 判断 | 展示 |
| --- | --- | --- |
| 文件头 | `--- `、`+++ ` | 强调色等宽文本 |
| 区块头 | `@@` | 弱化强调背景或文字 |
| 新增行 | `+`，但不是 `+++ ` | 成功色 |
| 删除行 | `-`，但不是 `--- ` | 危险色 |
| 截断提示 | 包含“已截断，省略” | 弱化提示色 |
| 其他上下文 | 其他文本 | 普通等宽文本 |

颜色不能成为唯一信息来源，diff 原始 `+`、`-`、`@@` 标记必须保留。

如果结果无法识别为预期修改摘要或属于旧事件，则回退到通用 `<pre>` 展示。

`NO_CHANGES` 不显示空 diff 区，只显示“内容无变化”和对应摘要。

## 11. 错误展示

### 11.1 状态

工具失败继续使用 `failed` 状态和当前危险色样式，不新增更细的前端状态枚举。

### 11.2 错误信息

- 优先显示后端 `errorMessage`。
- `errorCode` 存在时在错误信息下方使用等宽弱化文本展示。
- `resultPreview` 中存在结构化错误内容时可以同时展示，但不能替代明确错误信息。
- 不把后端异常栈、内部类名或未脱敏参数拼接到页面。
- 前端不维护完整错误码中文映射，后端中文 `message` 是主要用户说明。

### 11.3 兼容行为

- 历史事件缺少 `errorCode` 时只显示 `errorMessage`。
- 历史事件缺少 `permissionType` 时按 `TOOL` 处理。
- 未知工具继续显示原始工具名和通用工具卡片。
- 参数或结果解析失败时回退为纯文本，不能导致消息列表渲染失败。

## 12. 实时事件与历史归并

### 12.1 工具调用主键

继续使用：

- 工具调用主键：`toolCallId`，缺失时使用 `eventId`。
- 所属助手消息：`messageId`，缺失时按现有 `turnId` 规则生成。

### 12.2 状态覆盖

同一工具调用按事件到达顺序更新：

```text
TOOL_APPROVAL_REQUIRED -> waiting_approval
TOOL_CALL_STARTED      -> started
TOOL_CALL_ENDED        -> completed / failed
```

事件合并时：

- 新状态覆盖旧状态。
- 结束事件覆盖开始事件的结果和耗时。
- 后续事件没有携带的授权展示字段可以继续保留，但状态结束后不得继续显示操作按钮。
- `argumentsText` 使用最新事件中的安全参数摘要。
- 重复 `eventId` 在历史归并时继续去重。

### 12.3 SSE 行为

- 收到工具事件前继续刷新待处理的助手文本 delta，保持工具轨迹顺序。
- SSE 断开或会话取消时，不凭空把已完成工具改为失败。
- 授权卡片的可操作性只以当前实时会话中的 `approvalId` 和状态为准。

### 12.4 历史行为

- 历史加载继续使用 `reduceSessionEventsToMessages`。
- 当前会话仍在流式执行时，不用历史结果覆盖本地实时消息。
- JSONL 只恢复结果引用；实时和历史工具项展开时都通过同一接口懒加载结果摘要，并在页面内按 `sessionId + resultId` 缓存成功请求。
- 历史页面不请求 LLM 使用的 12,000 字符 diff，也不尝试恢复完整 diff。

## 13. 右侧状态与通知

保持现有实现：

- `waiting_approval` 和 `submitting` 计入待授权数量。
- `started` 工具可以作为当前活动工具展示。
- 工具完成或失败后自动退出活动状态。
- 不增加文件工具专属全局通知。
- 不在右侧通知区重复展示完整授权卡片或 diff。

## 14. 响应式与可访问性

- 保持现有 QQ 主题色、圆角、边框和紧凑密度。
- 工具标题按钮继续使用 `aria-expanded`。
- 状态文本必须与颜色同时存在。
- 授权按钮必须具有明确文本，并在提交时设置 `disabled`。
- 路径和结果区域支持键盘滚动。
- 长路径使用 `title` 提供完整值。
- diff 颜色不是唯一标识，保留原始行前缀。
- 复制按钮提供可访问名称，例如“复制工具参数”“复制工具结果”。
- 移动端允许授权按钮换行，不能出现横向溢出。

## 15. 前端代码调整

### 15.1 `mboo-web/src/lib/session-types.ts`

- 不新增事件类型。
- 保持现有 payload 字段类型。
- `ToolCallEndedPayload.errorCode` 继续作为可选字段。
- 后端文件工具事件仍通过现有联合类型进入前端。

### 15.2 `mboo-web/src/app/page.tsx`

调整内容：

1. 更新 `TOOL_LABELS`。

## 17. 验收清单

### 17.1 工具识别

- 五个文件工具显示正确中文名称。
- 工具轨迹默认只显示一行汇总，助手消息流式执行期间显示“调用工具中”，收到助手终态后显示已调用一个或多个工具。
- 展开汇总后显示工具调用记录，单条记录再次展开后才显示具体参数和返回结果。
- 未知工具仍可通过通用卡片展示。
- 折叠标题能够显示目标路径且不会挤压状态标签。
- 展开区域保留原始工具名和完整安全参数。

### 17.2 授权

- 工作区内读取直接进入运行状态，不展示授权卡片。
- 工作区外读取正确展示 `READ` 授权目录。
- 工作区内外写入正确展示 `WRITE` 授权目录。
- 授权卡片不出现修改前 diff 或文件完整内容。
- 三个审批按钮的状态、禁用和失败恢复符合设计。
- 拒绝或超时后即使没有开始事件，也能显示失败结束状态。

### 17.3 结果

- 查找、搜索和读取结果保留等宽格式及换行。
- 修改成功后展示摘要和执行后 diff。
- diff 新增、删除、区块头和截断提示样式正确。
- `NO_CHANGES` 不显示空 diff。
- 4,000 字符事件结果不被前端再次截断。
- 参数和结果复制内容与当前展示内容一致。

### 17.4 错误

- 文件工具失败显示后端中文错误和真实错误码。
- 参数或结果不是合法 JSON 时正常回退为纯文本。
- 结果引用缺失、结果文件不存在或内容损坏时仅当前工具项显示加载失败，页面其他历史内容正常展示。
- 原始编辑内容和整文件写入内容不会出现在参数区。

### 17.5 实时与历史

- 实时事件能够按授权、开始、结束顺序更新同一工具项。
- 允许后状态由 SSE 推进，前端不提前伪造成功。
- JSONL 历史和实时 SSE 对同一事件展示一致。
- 历史未结束授权显示“授权请求已失效”且不可操作。
- 当前流式会话不会被历史加载覆盖。

### 17.6 布局与可访问性

- 当前 QQ 主题和整体页面布局不发生无关变化。
- 长路径、长参数、长结果和 4,000 字符 diff 不造成页面横向溢出。
- 移动端授权按钮可以换行并保持可点击。
- 工具状态、diff 行和授权按钮具有可读文本，不只依赖颜色。
