# 工具与工作区权限方案

## 1. 目标

在保留按工具授权能力的基础上，统一文件读取、写入和命令执行权限，并按会话工作区控制路径型授权范围。

本方案描述会话内的工具调用授权内核，不实现全局权限管理。权限内核现已接入文件、命令和网络工具；文件操作细节见 `docs/Code-Agent文件工具后端接入设计.md`，网络边界和结果契约见 `docs/Code-Agent网络工具设计.md`。

## 2. 权限类型

每个工具通过 `@ToolPermission` 显式声明基础权限类型。遗漏配置时在工具注册阶段（`ToolPermissionRegistry.register`）直接失败，避免工具绕过权限检查。普通工具生成零个或一个权限要求；`COMMAND` 和 `NETWORK` 可以由专用评估器生成有序权限链，例如工作区外命令的 `WRITE -> COMMAND`、私有网页抓取的 `TOOL -> NETWORK`。

| 类型 | 含义 |
| --- | --- |
| `NONE` | 工具无需授权 |
| `TOOL` | 按工具名称授权 |
| `READ` | 允许读取指定目录及其子目录 |
| `WRITE` | 允许读写指定目录及其子目录，包含 `READ` 权限 |
| `COMMAND` | 允许执行符合内置规则、只读分类或会话精确指纹授权的 Shell 命令 |
| `NETWORK` | 允许访问经过规范化和安全分类的精确私有网络来源 |

路径型工具（`READ` / `WRITE`）还需配置：

- `pathParam`：路径参数名称，例如 `path`。
- `pathKind`：参数表示文件还是目录。`FILE` 申请其父目录，`DIRECTORY` 申请目录本身。

可选配置：

- `title` / `description`：授权卡片文案；为空时由服务端按权限类型生成默认文案。

工具名与 LangChain4j `@Tool` 一致：优先使用注解 `name`，为空则使用方法名。

## 3. 权限判定规则

会话工作区由 `Sessions.workspacePath` 确定，会话创建后不再变更。

- 默认允许读取工作区及其子目录，不需要用户授权。
- 读取工作区外的目录需要 `READ` 或 `WRITE` 授权。
- 所有写入都需要 `WRITE` 授权，包括写入工作区。
- `WRITE` 授权可以满足同一目录下的读取请求。
- 目录授权包含该目录及其全部子目录。
- 相对路径以会话工作区为基准解析，绝对路径保持原含义。

单次评估结果由 `PermissionCheck` 表示：

| 状态 | 含义 |
| --- | --- |
| `ALLOWED` | 已满足权限，可直接执行 |
| `NEED_ASK` | 需要向用户弹窗授权 |
| `ERROR` | 评估失败（参数/路径等硬错误），不弹授权卡片，直接返回错误 |

授权结果的有效期：

- `ALLOW_ONCE`：仅允许当前工具调用，不持久化。
- `ALLOW_SESSION`：在当前会话中持续有效，持久化到 `Sessions.metadataJson`。
- `DENY`：拒绝当前调用，不持久化为黑名单。

会话权限模式（`permissionMode`）控制 `NEED_ASK` 的处理方式，按会话存储在 `metadataJson` 顶层，详见 ADR-0001（`docs/会话权限模式.md`）：

| 模式 | 含义 |
| --- | --- |
| `DEFAULT`（默认权限） | 按上述规则正常评估，`NEED_ASK` 弹授权卡片等待用户决策 |
| `FULL_ACCESS`（完全访问） | `NEED_ASK` 自动视为 `ALLOWED`，不再弹授权卡片 |

- 完全访问只转换 `NEED_ASK`；`ERROR`（路径无法解析等硬错误）与内置命令黑名单（`COMMAND_PERMISSION_DENIED`）照常拒绝。
- 每次权限评估实时读取模式，初评与执行前复核（第 5 节）一致生效；会话中途切换只影响下一次调用的评估，已挂起的授权卡片保持原状。
- 完全访问下自动通过不产生 `TOOL_APPROVAL_REQUIRED` 事件，也不写入会话授权数据；已持久化的会话授权继续有效。
- 字段缺失或非法时按 `DEFAULT` 处理，兼容历史会话。

## 4. 会话权限存储

权限数据放在 `metadataJson` 的独立 `permissions` 节点中，更新时保留其他元数据。

```json
{
  "permissionMode": "DEFAULT",
  "permissions": {
    "allowedTools": [],
    "readPaths": ["D:\\shared\\docs"],
    "readWritePaths": ["D:\\output"],
    "allowedCommands": ["v1:0123456789abcdef..."],
    "allowedNetworkOrigins": ["http://127.0.0.1:8080"]
  }
}
```

字段含义：

- `allowedTools`：本会话已允许的 `TOOL` 类型工具。
- `readPaths`：本会话允许读取的目录。
- `readWritePaths`：本会话允许读写的目录。
- `permissionMode`（顶层字段）：会话权限模式，见第 3 节；缺失时按 `DEFAULT` 处理。
- `allowedCommands`：本会话精确允许的版本化命令指纹，绑定原始命令、真实工作目录和 Shell 身份。
- `allowedNetworkOrigins`：本会话精确允许的私有网络来源，固定为 `scheme://normalizedHost:effectivePort`，不支持通配符。

工作区默认读取权限由 `workspacePath` 动态派生，不重复写入 `metadataJson`。

更新策略：

- 通过 `SessionService.updatePermissions` 修改 `permissions` 节点。
- 底层统一走 `updateMetadataJson`：按 `sessionId` 分段锁串行化读改写，并以旧值 CAS 写回，失败重试，避免并发覆盖。
- 新会话可通过 `POST /session/chat` 的可选 `permissionMode` 初始化初始模式；已有会话通过 `PUT /session/{id}/permission-mode` 修改，复用同一 `updateMetadataJson` 并发保护。

会话归档和取消归档后权限继续保留；删除会话时权限随会话数据一起删除。

## 5. 工具调用流程

1. 工具注册时由 `AiCodeServiceFactory` 调用 `ToolPermissionRegistry.register`，读取并校验 `@ToolPermission`。
2. 工具统一由 `PermissionToolExecutor` 包装执行。
3. `beforeToolExecution` 调用 `ToolApprovalService.requestIfNeeded`，通过 `ToolPermissionEvaluatorRegistry` 生成权限链：
   - `ALLOWED`：直接发送 `TOOL_CALL_STARTED`；
   - `WAITING`：登记待授权、发送 `TOOL_APPROVAL_REQUIRED` 并阻塞等待；
   - `INVALID`：不发送开始或授权事件，由工具执行器返回结构化错误。
4. `PermissionToolExecutor` 调用 `awaitAuthorization` 顺序等待当前权限阶段，并在全部阶段完成后重新生成权限链执行最终复核。
5. 只有全部权限要求满足后才发送一次 `TOOL_CALL_STARTED`；拒绝、超时或复核失败时不执行工具。
6. 用户选择会话授权时，先将对应工具、目录、命令指纹或私有网络来源写入 `metadataJson`，再完成当前阶段的 Future 并推进下一阶段。

关键时序：

```text
模型发起工具调用
  -> requestIfNeeded 生成 ToolPermissionChain
  -> 逐项评估 PermissionCheck
  -> NEED_ASK：落盘/推送当前阶段 TOOL_APPROVAL_REQUIRED，阻塞等待
  -> 推进后续授权阶段
  -> 全部阶段完成后重新生成权限链并最终复核
  -> 通过则发送 TOOL_CALL_STARTED 并执行工具，否则返回错误结果
```

每个授权阶段的等待时间保持 10 分钟。超时与用户拒绝使用不同错误码（见第 10 节）。

服务重启后，已持久化的会话权限继续有效；内存中尚未处理的授权请求失效。前端历史回放时，未结束的授权卡片标记为“授权请求已失效”且不可点击，用户需要重新发起请求。

## 6. 授权事件

沿用现有 `TOOL_APPROVAL_REQUIRED` 事件，在现有工具调用信息之外包含：

- `permissionType`：本次申请的权限类型。
- `grantPath`：申请授权的规范化绝对目录，仅 `READ`、`WRITE` 使用。
- `grantOrigin`：申请授权的规范化私有网络来源，仅 `NETWORK` 使用。
- `approvalIndex`：当前授权阶段，从 1 开始。
- `approvalCount`：本次实际需要用户处理的授权阶段总数。

`TOOL` 类型继续展示工具名称和用途，不展示目录。历史事件没有 `permissionType` 时按 `TOOL` 兼容处理。

同一工具调用同一时刻只展示一个可操作授权卡片。后续阶段使用新的 `approvalId` 和相同的 `toolCallId` 替换前一阶段。

路径无法解析、参数缺失等 `ERROR` 场景不发送授权事件，直接在工具结果中返回错误。

## 7. 前端展示

路径权限卡片必须明确展示授权目录，并显示“包含其子目录”，避免用户误解授权范围。

| 操作 | 文案 |
| --- | --- |
| `TOOL` 会话授权 | 本会话始终允许此工具 |
| `READ` 会话授权 | 本会话允许读取此目录 |
| `WRITE` 会话授权 | 本会话允许读写此目录 |
| `COMMAND` 会话授权 | 本会话允许此命令 |
| `NETWORK` 会话授权 | 本会话允许访问此网络来源 |
| 单次授权 | 仅允许本次 |
| 拒绝 | 拒绝 |

“本会话”表达授权有效期，卡片中的工具名称或目录表达授权范围。

## 8. 路径安全检查

路径检查由 `FilePermissionUtil` 统一实现，采用严格模式：

1. 将工作区、授权目录和工具参数转换为绝对路径并执行规范化。
2. 使用 `Path.startsWith()` 判断目录包含关系，不使用字符串前缀比较。
3. 对已存在路径解析真实路径，防止符号链接或 Windows junction 跳出已授权目录。
4. 目标路径尚不存在时，从最近的已存在父目录解析真实路径，再拼接剩余路径。
5. 工具实际执行前通过重新生成权限链再次检查：
   - `ALLOW_ONCE`：本次授权目录必须与当前参数解析结果一致；
   - 会话授权：重新评估会话权限是否仍覆盖目标目录。

无法正确解析或验证的路径默认拒绝访问。

## 9. 已接入的文件工具

当前权限内核已接入以下真实文件工具：

| 工具名 | 权限类型 | 路径语义 |
| --- | --- | --- |
| `glob_files` | `READ` | `DIRECTORY` |
| `search_text` | `READ` | `DIRECTORY` |
| `read_file` | `READ` | `FILE` |
| `edit_file` | `WRITE` | `FILE` |
| `write_file` | `WRITE` | `FILE` |

原无副作用演示工具 `FileWritePermissionDemoTool` / `demoWriteFile` 已删除。五个文件工具继续复用本方案定义的目录授权、会话权限持久化和执行前复核机制；文件编码、忽略规则、原子写入、diff 和错误码等实现细节以后端接入设计为准。

网络工具也已接入当前权限内核：`web_search` 使用 `TOOL` 权限；`web_fetch` 由 `NETWORK` 专用评估器生成权限链，公共目标只申请 `TOOL`，私有目标在能力总闸开启后申请 `TOOL -> NETWORK`。系统硬拒绝目标和关闭的私有网络能力不会生成授权卡片。

当前仍不提供独立权限撤销界面。

## 10. 错误码与结果结构

权限相关错误码由 `ToolPermissionErrorCode` 统一管理：

| 错误码 | 含义 |
| --- | --- |
| `PERMISSION_DENIED` | 用户拒绝本次工具调用 |
| `PERMISSION_TIMEOUT` | 等待用户授权超时 |
| `PERMISSION_INVALID_PATH` | 路径参数缺失、格式错误或无法解析授权目录 |
| `PERMISSION_UNKNOWN_TYPE` | 未知的工具权限类型 |
| `PERMISSION_INTERRUPTED` | 授权等待被中断 |
| `PERMISSION_ERROR` | 授权处理过程出现未分类错误 |
| `PERMISSION_PATH_CHANGED` | 执行前复核发现路径与授权时不一致 |
| `PERMISSION_REVOKED` | 会话级授权已不满足当前路径 |
| `COMMAND_PERMISSION_DENIED` | 内置命令规则明确禁止命令 |
| `COMMAND_PERMISSION_CHANGED` | 执行前命令指纹与授权时不一致 |

权限失败结果由 `PermissionToolExecutor` 按统一工具结果结构序列化为 JSON，至少包含：

- `success=false`
- `status=FAILED`
- `errorCode`
- `message`
- `data=null`
- `permissionType`（如有）
- `grantPath`（如有）
