# 上下文窗口自定义设计

## 1. 状态

- 状态：已实施并验证
- 目标：允许用户按模型保存自定义上下文窗口上限，并在上下文用量控件中查看和调整。
- 本文档只记录已确认事实、候选设计和待决问题；候选项在确认前不作为实施结论。

## 2. 当前需求

- 暂无上下文 usage 时，上下文用量控件显示当前模型的上下文窗口上限。
- 点击上下文用量控件后打开调节面板，通过滑块调整上下文上限。
- 滑块最大值为当前模型从 models.dev 获取的上下文窗口上限。
- 调整结果按模型 ID 持久化到新表；再次选择同一模型时优先使用已保存值。
- 需要确定滑块下限及 `0` 的语义。

## 3. 已确认的现状

### 3.1 模型能力来源

- `ModelMetadataService` 在应用启动时从 models.dev 加载模型能力。
- `ModelInfo.limit.context` 是 models.dev 提供的模型上下文窗口能力上限。
- `ModelOptionService` 将供应商实际模型 ID 与 models.dev 能力匹配，应用运行期间不刷新。

### 3.2 当前上下文窗口用途

当前 `ModelInfo.limit.context` 同时用于：

- 前端上下文圆环的分母和 tooltip 文案。
- 后端 70% 自动上下文压缩触发判断。
- 压缩后历史占窗口 50% 的目标预算。
- 新用户消息的硬预算检查。
- 保存 `mboo_chat_memory.last_context_limit`，用于跨模型切换时的保守压力判断。

主模型请求当前没有发送“上下文窗口”参数，也没有按上下文窗口动态设置 `maxOutputTokens`。因此，自定义上下文上限不能直接改变供应商模型的物理能力，只能成为应用侧预算策略，除非同时补充主模型输出预算控制。

### 3.3 当前硬预算预留

- 工具定义和估算误差固定预留 `4,096` Token。
- 助手输出最多预留 `32,768` Token，且不超过模型的 `limit.output`。
- 当上下文窗口小于或等于上述预留总量时，现有实现会跳过硬预算拒绝逻辑。

## 4. 候选领域模型

| 对象 | 建议代码名 | 含义 |
| --- | --- | --- |
| 模型上下文能力上限 | `maxContextLimit` | models.dev 提供的当前模型物理窗口上限，只读 |
| 模型上下文偏好 | `ModelContextPreference` | 用户按供应商实际模型 ID 保存的自定义值 |
| 生效上下文上限 | `effectiveContextLimit` | 有有效偏好时使用偏好，否则使用能力上限 |

候选不变量：

```text
minimumContextLimit <= effectiveContextLimit <= maxContextLimit
```

模型能力上限与生效上下文上限必须分字段表达，不能覆盖 `ModelInfo.limit.context`，否则前端无法知道滑块最大值，后端也无法区分远端能力变化和用户偏好。

以上领域对象和字段区分已确认。

## 5. 持久化边界

新增独立表，记录应用级、按模型 ID 生效的偏好，不放入 session 元数据：

```text
mboo_model_context_preference
├── model_id TEXT PRIMARY KEY
├── context_limit INTEGER NOT NULL
├── created_at TEXT
└── updated_at TEXT
```

设计理由：

- 需求明确要求“根据模型名记录”，不是按 session 记录。
- 同一模型跨会话复用设置。
- 与 models.dev 能力目录分离，远端能力仍是只读事实。

## 6. 下限原则

不建议允许滑到 `0`：

- `0` 无法清晰区分“零 Token”“禁用限制”和“恢复模型默认值”。
- 如果需要恢复默认，应提供独立的“恢复模型上限”操作，而不是复用数值 `0`。

最终下限为 `100,000` Token。模型能力上限低于 `100,000` 时，生效值只能等于模型能力上限，不提供无意义的调节区间。

## 7. 已确认决策

### D1. 自定义值是统一的输入上下文预算上限

`effectiveContextLimit` 同时约束：

- 前端圆环分母和无 usage 时的窗口上限展示。
- 70% 自动压缩触发判断。
- 压缩后历史占窗口 50% 的目标预算。
- 新用户消息硬预算检查。
- `mboo_chat_memory.last_context_limit` 历史窗口记录和跨模型压力判断。

自定义值只作为主模型输入上下文侧的应用预算，不修改主模型的输出 Token 参数。模型输出仍由模型服务自身能力和现有请求行为决定，因此该值不代表“输入加输出”的总请求硬上限。

models.dev 的 `ModelInfo.limit.context` 继续表示只读能力上限，不被用户偏好覆盖。

### D2. 下限和输出行为

- 最低值固定为 `100,000` Token；模型能力上限低于该值时，最低值退化为模型能力上限，滑块没有可调范围。
- 不允许 `0`；恢复默认通过独立操作删除偏好或设置为模型能力上限。
- 不根据自定义值设置或缩小主模型 `maxOutputTokens`；输出仍按当前模型服务行为执行。

因此，`effectiveContextLimit` 的约束范围是输入上下文预算、上下文圆环和压缩策略，不是输入与输出之和的物理请求上限。

### D3. 远端能力变化时保留原偏好

- 读取偏好时使用 `min(savedContextLimit, maxContextLimit)` 计算生效值，不因 models.dev 上限降低而修改数据库原值。
- 远端能力上限回升后，原偏好可以自动恢复。
- 所有新写入仍必须位于当前模型的 `100,000` 到 `maxContextLimit` 之间。
- 任意时刻返回前端和参与预算计算的 `effectiveContextLimit` 都不能超过当前 `maxContextLimit`。

### D4. 滑块显式保存

- 拖动滑块只更新面板内的草稿值，不请求后端、不改变当前圆环分母和预算策略。
- 用户点击“保存”后写入数据库；保存成功后再更新当前模型的生效值和圆环。
- 保存失败时保留原生效值，在面板内展示错误，草稿值不冒充已生效值。
- 切换模型或关闭面板时丢弃未保存草稿。

### D5. 恢复默认删除偏好

- “恢复模型上限”删除当前模型的偏好行，生效值立即回到当前 models.dev 能力上限。
- 用户保存的草稿值等于当前模型能力上限时，也按恢复默认处理，不保存冗余记录。
- 删除偏好后，models.dev 能力上限将来提高或降低时，生效值自动跟随。

### D6. 滑块使用十进制 1K 粒度

- 普通档位每次调整 `1,000` Token，与现有 `formatTokens` 的十进制 `K` 口径一致。
- 键盘方向键每次调整 `1,000` Token。
- models.dev 能力上限不是 `1,000` 的整数倍时，额外把精确能力上限作为最后一档，不能向下取整。
- 后端仍按整数 Token 校验，不依赖前端步长保证合法性。

### D7. 运行期间不修改生效值

- 聊天或主动上下文压缩执行期间，面板可以查看但禁用滑块、保存和恢复默认。
- 保存成功的新值从下一次聊天或主动压缩开始参与预算。
- 保存成功后，当前闲置界面的圆环立即用新生效上限重新计算；正在运行的 turn 不被追溯修改。

### D8. 摘要模型使用自身模型偏好

- 自动或主动压缩最终选中哪个摘要模型，就读取该模型 ID 对应的上下文偏好。
- 上一轮模型作为摘要模型时使用上一轮模型的偏好；回退到当前 UI 模型时使用当前模型的偏好。
- 摘要模型没有偏好时使用其当前 models.dev 能力上限。
- 摘要保留候选、50% 目标预算和超大 turn 判断统一使用摘要模型的生效上下文上限。

### D9. 无 usage 时通过提示和面板显示上限

- `32px` 圆环继续显示灰色空环，不在圆心塞入可能溢出的 Token 数值。
- 鼠标悬浮和键盘聚焦文案改为“上下文上限 {effectiveContextLimit}”。
- 点击面板常驻显示生效上限和 models.dev 模型能力上限。
- `aria-label` 使用同一上限文案，不再使用“暂无上下文用量数据”。

### D10. 偏好按模型 ID 全局复用

- 新表主键只使用供应商实际模型 ID，区分大小写，不写入 `base_url` 或 provider 标识。
- 同一模型 ID 在不同供应商配置间会复用偏好。
- 读取时仍按当前 models.dev 能力上限裁剪，避免跨供应商复用导致超出当前模型能力。

### D11. 能力上限低于 100K 时只读展示

- 点击圆环仍打开面板并显示模型固定上限。
- 滑块和保存操作禁用，不构造无意义的自定义范围。
- 数据库存在该模型偏好时仍允许“恢复模型上限”，便于清理跨供应商遗留偏好；没有偏好时恢复操作禁用。

## 8. 后端接口

### 8.1 查询

```http
GET /config/modelContextLimit?modelId={modelId}
```

返回：

```text
ModelContextLimitResp
├── modelId
├── minimumContextLimit
├── maximumContextLimit
├── configuredContextLimit
├── effectiveContextLimit
└── adjustable
```

`configuredContextLimit` 返回数据库原值，允许因 models.dev 能力降低而暂时高于 `maximumContextLimit`；`effectiveContextLimit` 始终经过上下限裁剪。

### 8.2 保存

```http
PUT /config/modelContextLimit?modelId={modelId}
Content-Type: application/json

{
  "contextLimit": 200000
}
```

- 模型必须属于当前可用模型。
- 模型能力上限至少为 `100,000`。
- 新值必须位于 `100,000` 到当前 models.dev 能力上限之间。
- 新值等于能力上限时删除偏好行。
- 成功后返回最新 `ModelContextLimitResp`。

### 8.3 恢复默认

```http
DELETE /config/modelContextLimit?modelId={modelId}
```

删除偏好行并返回最新默认状态。接口幂等，行不存在时仍返回成功。

### 8.4 前端代理

```text
GET    /api/model/{modelId}/context-limit
PUT    /api/model/{modelId}/context-limit
DELETE /api/model/{modelId}/context-limit
```

模型 ID 必须继续使用 URL 编码。

## 9. 后端生效流程

```text
models.dev ModelInfo.limit.context
  + mboo_model_context_preference.context_limit
  -> ModelContextPreferenceService 计算 effectiveContextLimit
  -> 前端圆环和面板
  -> 70% 自动压缩判断
  -> 50% 压缩目标与保留 turn 选择
  -> 新消息硬预算检查
  -> last_context_limit 持久化
```

摘要模型预算按摘要模型 ID 单独解析。主模型请求不新增 `maxOutputTokens`。

## 10. 前端交互

- 模型详情加载成功后并行加载该模型上下文偏好；两者都成功后才允许打开可调面板。
- 模型快速切换沿用请求序号，迟到响应不能覆盖当前模型。
- 圆环使用 `effectiveContextLimit` 计算占比；模型切换仍清空旧模型 usage。
- 无 usage 时 tooltip、焦点提示和 `aria-label` 显示生效上限。
- 点击圆环打开独立弹出面板，不能把滑块嵌套在按钮内部。
- 面板显示生效上限、模型最大上限、草稿值、滑块、保存和恢复操作。
- 普通档位为十进制 `1K`，非整步的模型最大值作为精确末档。
- 点击外部、切换模型或关闭面板时丢弃未保存草稿。
- 聊天或主动压缩运行期间禁用修改操作。

## 11. 失败处理

| 场景 | 行为 |
| --- | --- |
| 未知模型 | 返回“模型不存在或未提供能力信息” |
| 保存值低于 `100K` | 返回“上下文上限不能低于 100.0K” |
| 保存值高于模型能力 | 返回“上下文上限不能超过模型能力上限” |
| 小窗口模型尝试保存 | 拒绝保存，前端正常情况下不发起请求 |
| 查询偏好失败 | 面板不可调，聊天仍可使用模型能力上限 |
| 保存或删除失败 | 保留原生效值和 usage 分母，在面板展示错误 |
| 数据库旧值高于当前能力 | 不报错，生效值临时裁剪到当前能力上限 |

## 12. 验收标准

- 无 usage 时圆环提示显示当前生效上下文上限。
- 点击圆环可打开包含 `1K` 粒度滑块的面板，最大档精确等于 models.dev 上限。
- 模型能力至少 `100K` 时可保存；低于 `100K` 时只读展示。
- 保存值按区分大小写的模型 ID 写入新表，跨会话和应用重启恢复。
- 保存最大值或点击恢复默认会删除偏好行。
- 旧偏好高于当前模型能力时临时裁剪但不修改数据库。
- 生效值统一用于圆环、70% 自动压缩、50% 压缩目标、硬预算和 `last_context_limit`。
- 摘要模型使用自己的模型偏好。
- 不设置主模型 `maxOutputTokens`。
- 执行 turn 运行期间不能修改，新值从下一次执行开始参与预算。
- 后端编译和前端生产构建通过。

## 13. 实施结果

- SQLite 新增 `mboo_model_context_preference`。
- 后端新增模型偏好查询、保存和恢复默认接口。
- 生效值已接入圆环、自动压缩、压缩目标、硬预算、摘要模型预算和 `last_context_limit`。
- 前端新增可交互弹出面板、`1K` 滑块、显式保存和恢复默认。
- 已验证后端接口的查询、保存、重新读取和恢复默认闭环，并恢复测试数据。
- 已通过后端编译、前端生产构建以及桌面和 `390×844` 窄屏界面检查。
