# 系统提示词设计

- 状态：已实施
- 日期：2026-08-09
- 相关文档：`docs/上下文管理与压缩设计.md`、`docs/工具与工作区权限方案.md`、`docs/术语表.md`

## 文档定位

本文档统一定义主 Code Agent 系统提示词的静态内容、运行时组成、工作区指令和运行环境上下文注入规则。摘要模型继续使用独立的摘要系统提示词，不属于本文档范围。

工作区根目录 `AGENTS.md` 和运行环境上下文注入已经按本文档实施。

## 目标

- 保持内置系统提示词、运行时环境事实、工作区指令和较早对话摘要之间的稳定边界与顺序。
- 自动加载工作区根目录的 `AGENTS.md`，并把内容作为工作区指令加入主模型上下文。
- 向主模型提供完成工作区任务所需且由运行时确定的项目环境事实。
- 让实际发送给主模型的组合系统消息与上下文预算估算使用相同内容。

## 已确认决策

### D1：第一版只读取工作区根目录的 AGENTS.md

- 工作区使用会话创建后固定的 `Sessions.workspacePath`。
- 只检查 `{workspacePath}/AGENTS.md`。
- 不读取全局规则、嵌套目录规则、`AGENTS.override.md` 或 `CLAUDE.md`。
- 不自动创建文件，不在文件缺失时提示用户，也不提供功能开关。
- `AGENTS.md` 是否被 Git 跟踪或忽略不影响加载。

### D2：每个执行 turn 使用一份不可变快照

- 每个 `CHAT` 执行 turn 开始时重新读取一次 `AGENTS.md`。
- 同一个 turn 内的初次模型请求和后续工具循环使用同一份工作区指令快照。
- turn 执行期间文件发生修改或删除，不改变当前快照；下一轮聊天重新读取。
- 主动上下文压缩也单独读取当前快照，但只用于预算计算，不发送给摘要模型。

### D3：工作区指令进入主模型的组合系统消息

组合系统消息顺序固定为：

```text
内置系统提示词
  -> 运行环境上下文
  -> 工作区指令
  -> 较早对话摘要
```

- 工作区指令使用 `<workspace-instructions source="AGENTS.md">` 边界。
- 边界中明确工作区指令不能覆盖内置安全、工具权限和工作区边界。
- 不向模型暴露 `AGENTS.md` 的绝对路径。
- 摘要模型继续使用独立固定系统提示词，不加载工作区指令。
- 运行环境上下文只表达运行时事实，不形成新的行为要求。

### D4：严格读取完整 UTF-8 文件

- 最大文件大小为原始字节数 `32 * 1024`。
- 允许 UTF-8 BOM，注入前移除 BOM。
- 仅含空白字符时视为空文件。
- 除移除 BOM 外，不修改换行、缩进或正文。
- 文件不存在或为空时正常继续，不追加空的工作区指令段。
- 文件超限、不是合法 UTF-8 或读取失败时拒绝当前操作，不静默忽略，也不截断加载。

### D5：工作区边界适用于指令文件真实路径

- `AGENTS.md` 是符号链接时解析真实目标。
- 真实目标仍位于真实工作区内时允许读取。
- 真实目标越过工作区边界时拒绝当前操作。

### D6：失败沿用现有执行事件生命周期

- 聊天加载失败发生在写入 `USER_MESSAGE` 和调用主模型之前。
- 新会话已经创建时不回滚会话和工作区，写入现有 `ERROR` 事件；用户修复文件后可以在原会话重试。
- 主动压缩加载失败使用现有压缩失败事件，不调用摘要模型。

### D7：工作区指令计入所有主上下文预算

- 工作区指令计入新用户消息硬预算。
- 工作区指令计入自动和主动压缩的压缩后目标预算。
- 工作区指令始终从文件快照加载，不进入历史摘要，也不发送给摘要模型。

### D8：不增加前端或 JSONL 展示

- 不新增工作区指令事件、接口或前端状态。
- 成功加载只记录不含正文的 `debug` 日志。
- 加载失败记录不含正文的 `warn` 日志。
- 日志允许包含 session ID、真实文件路径、原始字节数和内容 SHA-256。

### D9：工作区指令具有项目规则优先级

- 内置系统规则、安全限制、工具权限和工作区边界始终优先。
- 工作区指令优先于当前聊天中的普通用户要求。
- 用户不能只通过聊天要求忽略工作区指令；需要改变规则时应修改 `AGENTS.md`。

### D10：不自动展开文件引用

- `@docs/rules.md`、Markdown 链接和普通文件路径都作为 `AGENTS.md` 正文原样注入。
- 加载器不递归读取引用文件。
- 工作区指令明确要求读取其他文档时，由主 Agent 使用现有文件工具按需读取。

### D11：沿用组合系统消息的 ChatMemory 持久化

- 第一版不重构现有 ChatMemory 系统消息持久化机制。
- 工作区指令正文会随组合系统消息保存到本地 SQLite，但不进入 JSONL 或前端。
- `AGENTS.md` 仍是事实来源；下一轮加载的新组合系统消息替换旧系统消息。

### D12：AGENTS.md 文件名遵循文件系统语义

- 加载器固定解析 `{workspacePath}/AGENTS.md`，不扫描或校正其他大小写变体。
- Windows 等大小写不敏感文件系统自然允许大小写不同的目录项。
- Linux 等大小写敏感文件系统只匹配精确的 `AGENTS.md`。
- 该规则不产生多个大小写候选文件的选择问题。

### D13：只加载普通文件

- 候选路径必须是普通文件。
- 目标仍位于真实工作区内的文件符号链接按 D5 处理后允许加载。
- 目录、设备文件和其他非普通文件拒绝当前操作，并返回“工作区 AGENTS.md 不是普通文件”。

### D14：用户错误信息不包含绝对路径

- 用户可见错误只包含 `AGENTS.md` 文件名和失败原因。
- 工作区绝对路径和指令文件真实路径只允许写入不含正文的后端日志。

### D15：拒绝包含 NUL 的内容

- 合法 UTF-8 内容中只要包含 `NUL` 字符，就视为非文本文件并拒绝当前操作。
- 除 UTF-8 BOM 和 `NUL` 规则外，不额外过滤或改写其他合法 UTF-8 内容。

### D16：使用“运行环境上下文”作为正式术语

- 正式术语为运行环境上下文（`Runtime Environment Context`）。
- 单个 turn 内确定且保持不变的实例称为运行环境快照（`Runtime Environment Snapshot`）。
- 不再使用容易与项目依赖、构建配置混淆的“项目环境信息”。

### D17：第一版只注入最小运行环境字段

运行环境上下文包含：

- 会话工作区绝对路径；
- 操作系统名称；
- 操作系统版本；
- CPU 架构；
- 实际命令 Shell 类型；
- Shell 可执行文件绝对路径；
- 当前日期；
- 系统时区。

第一版不探测或注入 Git 分支与状态、构建工具、语言运行时、环境变量、主机名、用户名、区域设置或工作区目录内容。

### D18：工作区绝对路径允许发送给主模型

- 运行环境上下文使用会话持久化的 `Sessions.workspacePath` 作为当前工作区绝对路径。
- 工作区绝对路径是相对路径解析和命令工作目录的核心事实，允许发送给主模型。
- `AGENTS.md` 经过符号链接解析后的真实来源路径仍不发送给模型。

### D19：组合系统消息使用固定层次

```text
内置系统提示词
  -> 运行环境上下文
  -> 工作区指令
  -> 较早对话摘要
```

- 内置系统提示词定义行为、信任边界和指令优先级。
- 运行环境上下文只提供事实，不形成行为要求。
- 工作区指令提供项目级行为指导。
- 较早对话摘要只恢复历史事实和仍有效的较早用户要求。

### D20：每个执行 turn 生成运行环境快照

- `CHAT` 和 `CONTEXT_COMPRESSION` 执行 turn 都在开始处理时生成一份运行环境快照。
- 同一聊天 turn 的初次模型请求和工具循环使用同一份快照。
- 日期只精确到天，不注入当前时刻。

### D21：运行环境采集失败不阻止操作

- 缺失的普通环境字段使用 `unknown`。
- 无法发现可用 Shell 时，Shell 类型和可执行文件使用 `unavailable`。
- 工作区路径继续使用会话持久化值。
- 运行环境上下文是辅助事实，采集不完整不能成为聊天或主动压缩的新故障点。

### D22：运行环境上下文只发送给主模型

- 主模型的组合系统消息包含运行环境上下文。
- 摘要模型不接收运行环境上下文。
- 聊天硬预算、自动压缩和主动压缩的压缩后预算都必须计入运行环境上下文。

### D23：沿用组合系统消息的持久化与展示边界

- 运行环境上下文允许随组合系统消息进入本地 ChatMemory。
- 不写入 JSONL，不新增接口、前端展示、专用事件或专用日志。

### D24：运行环境上下文使用标签包裹的多行 JSON

格式固定为：

```text
<runtime-environment>
{
  "workspacePath": "...",
  "operatingSystem": {
    "name": "...",
    "version": "...",
    "architecture": "..."
  },
  "shell": {
    "type": "powershell",
    "executable": "..."
  },
  "currentDate": "2026-08-09",
  "timezone": "Asia/Shanghai"
}
</runtime-environment>
```

- 使用 JSON 序列化器生成正文，不手工转义路径、引号或控制字符。
- 字段名称和顺序保持稳定，方便模型理解、日志排查和预算估算。
- 标签外不重复输出相同环境信息。

### D25：运行环境字段使用稳定值规范

- `operatingSystem.name`、`version` 和 `architecture` 使用 JVM 系统属性原值，缺失时使用 `unknown`。
- `shell.type` 只使用 `powershell`、`posix` 或 `unavailable`。
- `shell.executable` 使用实际 Shell 可执行文件绝对路径；无法发现时使用 `unavailable`。
- `currentDate` 使用 `yyyy-MM-dd`。
- `timezone` 使用 `ZoneId.systemDefault().getId()` 返回的标识；无法取得时使用 `unknown`。

### D26：Shell 信息复用命令工具的真实发现结果

- 运行环境快照调用现有 `ShellResolver.resolve()` 获取 Shell 类型和可执行文件。
- 第一次调用允许执行现有候选 Shell 探测，之后复用 `ShellResolver` 的应用级缓存。
- 探测失败只把两个 Shell 字段写为 `unavailable`，不阻止聊天或主动压缩。
- 系统提示词不得维护独立的 Shell 猜测逻辑，避免与 `run_command` 实际行为不一致。

### D27：工作区失效时仍注入持久化路径

- 运行环境快照直接使用 `Sessions.workspacePath`，不重新执行真实路径解析。
- 会话创建后目录被移动、删除或暂时不可访问时，仍注入原持久化绝对路径。
- 第一版不增加 `workspaceAvailable` 字段，也不因路径失效阻止 turn。
- 后续文件或命令操作继续由现有工具返回具体路径错误。

## 实施结构

- `SystemPromptService` 统一生成快照、渲染基础组合系统消息并追加会话摘要。
- `WorkspaceInstructionLoader` 严格读取工作区根目录的 `AGENTS.md`。
- `RuntimeEnvironmentProvider` 使用会话工作区、JVM 属性、系统日期与时区和 `ShellResolver` 生成运行环境上下文。
- `AiCodeService` 使用 LangChain4j `@V` 参数填充 `prompt/system-prompt.txt` 中的两个运行时模板变量。
- `AiCodeServiceFactory.systemMessageTransformer` 在同一条基础组合系统消息后追加会话摘要。
- `ContextManagementService` 使用 `SystemPromptService` 生成的相同组合内容计算硬预算和压缩目标。

## 待确认决策

- 无。

## 实施方案

1. 新增工作区指令加载组件，负责真实路径边界校验、普通文件校验、32 KiB 限制、严格 UTF-8 解码、BOM 和 NUL 处理、空白识别以及日志摘要字段生成。
2. 新增运行环境快照组件，使用会话工作区路径、JVM 系统属性、系统日期与时区以及 `ShellResolver` 生成固定结构的多行 JSON。
3. 为 `SessionTurn` 补充数据库中固定的会话工作区路径，使聊天和主动压缩都只使用 `Sessions.workspacePath`。
4. 在聊天写入 `USER_MESSAGE` 前生成运行环境快照和工作区指令快照，并把同一组快照同时传给上下文预算处理和主 AI Service。
5. 在 `prompt/system-prompt.txt` 中增加运行时模板变量，并使用 LangChain4j `@V` 把格式化后的环境块和工作区指令块绑定到一次 `AiCodeService.chatStream` 调用。
6. 保留现有 system message transformer，在“内置提示词 + 运行环境上下文 + 工作区指令”之后追加会话摘要。
7. 调整 `ContextManagementService`，使用与实际主请求一致的基础组合系统消息计算硬预算和压缩后目标。
8. 主动压缩开始时生成独立的两类快照，只参与预算选择；摘要输入和摘要系统提示词保持不变。
9. 修正静态系统提示词中的项目规则优先级，并更新现有上下文管理设计文档；不新增接口、数据库结构、事件类型或前端改动。

## 验收场景

1. 根目录没有 `AGENTS.md` 或文件为空时，聊天和主动压缩保持原行为。
2. 有效 `AGENTS.md` 在本轮主模型初次请求和工具循环中持续生效。
3. turn 运行期间修改文件，本轮快照不变，下一轮使用新内容。
4. UTF-8 BOM 文件正常加载，正文除 BOM 外保持原样。
5. 超过 32 KiB、非法 UTF-8、包含 NUL、读取失败、不是普通文件或符号链接越界时，聊天不写 `USER_MESSAGE`、不调用主模型，并写现有 `ERROR` 事件。
6. 新会话首次加载失败后保留会话，修复文件后可以在原会话重试。
7. 主动压缩加载失败时写压缩失败事件，不调用摘要模型。
8. 工作区指令计入硬预算和压缩目标，但不进入摘要模型输入。
9. 被 Git 忽略的根目录 `AGENTS.md` 仍然加载。
10. `AGENTS.md` 内的文件引用不自动展开；用户错误不包含绝对路径，模型只看到会话工作区路径，不看到指令文件解析后的真实来源路径。
11. 主模型收到固定结构的运行环境上下文，字段值与当前会话、JVM 和 `ShellResolver` 一致。
12. 包含引号、反斜杠或非 ASCII 字符的工作区与 Shell 路径由 JSON 正确转义。
13. 同一聊天 turn 的模型工具循环使用同一运行环境快照；下一 turn 重新生成日期和其他可变环境事实。
14. Shell 探测失败时环境字段为 `unavailable`，聊天和主动压缩仍可继续。
15. 工作区目录失效时仍注入持久化路径，具体工具调用按现有规则失败。
16. 运行环境上下文计入聊天硬预算和压缩目标，但不发送给摘要模型，也不进入 JSONL 或前端。
